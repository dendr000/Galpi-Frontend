## 1. 요청과 배경

| 요청(원문) | 결정 |
|---|---|
| "작품 페이지에서 하나의 캐릭터의 본문을 보려면 캐릭터 그리드에서 하나 누르고 내려가거나, 제일 아래에서 이름만 보고 누가 누군지 찍거나 골라서 바꾸는 수밖에 없는데... 좀 더 보기 편한 방법 없으려나? 그냥 아예 모달로 크게 띄워서 오른쪽에 캐릭터인포박스두고 왼쪽 넓은 곳에 본문을 볼 수 있게 하는 식이라거나." | 큰 창(모달)으로 본문을 보는 방법을 추가한다 (M2) |
| "전에 캐릭터 카드 하나 선택하면 자동으로 본문 있는 곳으로 내려가는 기능 있었는데 지금은 아예 없더라." | 카드 선택 시 본문으로 부드럽게 이동하는 동작을 되살린다 (M1) |
| 질문 1 답: "B" / 질문 2 답: "B" (권장안으로) | 카드 클릭은 지금처럼 선택만 한다. 큰 창은 돋보기 버튼이나 더블클릭으로 연다. 설정은 앱 전체에 하나만 둔다 |

한 줄 정의: 작품 페이지에서 캐릭터 본문을 (1) 선택하면 자동으로 이동해 보거나 (2) 큰 창에서 이웃 캐릭터로 넘겨 가며 볼 수 있게 한다.

## 2. 목표와 비목표

- 목표
  - 카드를 선택하면 아래 본문 위치로 이동하고, 본문에서 그리드로 쉽게 돌아온다.
  - 큰 창: 왼쪽에 넓은 본문, 오른쪽에 인포박스. 방향키로 이전/다음 캐릭터, Esc로 닫기.
  - 설정(앱 전체, 이 PC에 저장): 자동 이동 켜기/끄기, 더블클릭으로 큰 창 열기 켜기/끄기.
- 비목표(지금 하지 않음)
  - 분할 보기(왼쪽 목록 + 오른쪽 본문), 오른쪽 서랍. 쓰면서 필요해지면 다음 계획서에서 다룬다.
  - 작품별 설정. 앱 전체 설정만 둔다.
  - 카드 클릭 자체를 큰 창으로 바꾸는 것(질문 1-A는 택하지 않음).
  - 큰 창 안에서 본문 편집.

## 3. 현재 상태·조사

- (코드를 읽어 확인함) 카드 클릭은 `CharacterGrid.jsx` 에서 `setActiveCharId` 만 호출하고 스크롤 코드가 없다.
- (코드를 읽어 확인함) 본문은 `CharacterDetailSection`, 인포박스는 `CharacterInfobox`(많은 속성을 받음), 맨 아래 이름 바는 `CharacterQuickNav` 가 그린다. 모두 `WorkDetailPage.jsx` 에서 조립한다.
- (git 이력 확인함) 카드 스크롤 코드는 장르 테마 커밋(b8dc4c5)에서 사라진 흔적이 있다. 그 코드가 요청하신 기능이었는지는 확정하지 못했다(추정).
- (코드를 읽어 확인함) `CharacterQuickNav.jsx` 의 주석에 "페이지 스크롤은 건드리지 않고 상세 정보만 전환"이라고 되어 있다. 맨 아래 이름 바는 일부러 스크롤하지 않는 것으로 보고, 자동 이동은 그리드 카드 클릭에만 건다.
- (코드를 읽어 확인함) 카드 요소 id 는 `char-card-{id}`, 본문 구역 id 는 `character-detail-section`. 이미 `useSelectCharFromUrl.js` 가 카드로 스크롤하는 방식을 쓴다.
- (추정, M2에서 확인) Ctrl+F 찾기창(`FindBar`)의 검색 범위가 문서 전체라서 큰 창 안 글자도 찾을 것이다.

## 4. 설계와 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 카드 클릭은 선택만, 큰 창은 돋보기 버튼과 더블클릭 | 그리드에서 정렬, 끌어서 순서 바꾸기, 훑어보기를 하는 중에 큰 창이 계속 열리면 방해된다 | 클릭하면 바로 큰 창 (질문 1-A) |
| 설정은 앱 전체 하나, `localStorage` 에 저장 | 단순하다. 작품별이 필요해지면 그때 확장 | 작품별 설정 (질문 2-A) |
| 자동 이동은 그리드 카드 클릭에만 적용, 선택 해제와 이름 바 클릭에는 적용 안 함 | 이름 바는 이미 본문 근처라 스크롤하면 오히려 어지럽다. 해제할 때 이동하면 어색하다 | 모든 선택 변경에 적용 |
| 본문에서 그리드로 돌아가는 "그리드로" 버튼을 본문 구역에 둔다 (선택한 카드로 이동) | 내려간 뒤 올라오는 것이 지금 가장 불편하다 | 맨 위로 가는 기존 버튼만 사용 |
| 큰 창은 같은 `activeCharId` 를 쓰고, 열면 선택도 같이 된다 | 닫은 뒤 아래 본문, URL, 인포박스와 어긋나지 않는다 | 모달 전용 선택 상태 |
| 큰 창의 이전/다음은 화면에 보이는 순서(필터, 정렬, 그룹 반영한 `displayChars` 기준) | 그리드에서 보이는 순서와 같아야 헷갈리지 않는다 | 전체 캐릭터 원래 순서 |
| 큰 창 안의 본문 렌더링은 `MarkdownRenderer` 를 그대로 쓰고, 구역 id(`character-detail-section`, `sec-chardetail`)는 쓰지 않는다 | id 가 둘이 되면 목차와 스크롤 대상이 꼬인다 | 본문 구역을 통째로 복제 |
| 큰 창 안 링크를 누르면 큰 창을 닫고 원래 링크 동작을 한다 | 큰 창 위에서 페이지가 바뀌면 혼란스럽다 | 큰 창 유지 |
| 방향키는 입력칸에 포커스가 있거나 글자 조합 중(IME)이면 무시 | 한글 입력을 방해하지 않는다 | 항상 반응 |

M1 은 설정 UI 없이 `localStorage` 값만 읽고, 설정 UI 는 M2 에서 함께 만든다. 각 단계가 끝날 때마다 동작하는 상태로 커밋, exe 재빌드한다.

## 6. 검증 방침

- 테스트(먼저 작성)
  - 설정: 기본값, 저장/읽기, 깨진 값, `localStorage` 사용 불가.
  - 자동 이동: 카드 클릭이면 호출, 같은 카드 다시 눌러 해제하면 호출 안 함, 설정이 꺼져 있으면 호출 안 함, 가려진(기밀) 카드의 첫 클릭은 선택하지 않으므로 호출 안 함.
  - 큰 창: 열림/닫힘, 이전/다음과 양끝 동작, 입력칸 포커스와 IME 조합 중 무시, Esc, 필터로 숨겨진 캐릭터는 건너뜀, 캐릭터가 하나뿐일 때, 링크 클릭 시 닫힘.
  - 변이 검사: 이동 조건, 양끝 처리, 입력칸 무시를 각각 깨뜨려 테스트가 실패하는지 확인.
- 눈으로 확인: 라이트/다크, 장르 테마(색을 `!important` 로 강제하므로 큰 창 글자색이 깨지지 않는지), 긴 본문 스크롤, 좁은 창 크기. Ctrl+F 가 큰 창 안 글자를 찾는지.
- 수락 기준: 카드 한 번 클릭 후 본문까지 스크롤 없이 도달, 큰 창에서 마우스 없이 방향키만으로 6명을 차례로 넘겨 본다.
- 실제 화면 확인은 테스트 작품(`localhost:9691/work/15`)에서만 한다.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 큰 창이 그리드의 드래그, 정렬 동작과 부딪힘 | 돋보기 버튼은 드래그 시작을 막는다(`draggable` 영역 밖 처리), 더블클릭은 드래그 중에는 무시 |
| 한글 입력(IME) 중 방향키, Esc 가 가로채임 | `isComposing` 이면 무시. 한글 찾기창에서 쓴 방식과 같게 |
| 큰 창 안 인포박스가 페이지의 인포박스와 id/상태를 공유 | 같은 컴포넌트를 쓰되 id 중복을 점검. 편집 기능이 있다면 큰 창에서는 읽기 위주로 둘지 M2 시작 때 확인 |
| 자동 이동 때문에 그리드 위치를 잃음 | "그리드로" 버튼과 설정 끄기 |
| Esc 가 찾기창, 우클릭 메뉴와 겹침 | 이미 처리된 Esc(`defaultPrevented`)면 큰 창은 닫지 않음 |
| 스크롤 복원(`useWorkDetailData` 의 저장된 Y 위치)과 충돌 | 첫 진입 복원 때는 자동 이동 억제, 테스트로 확인 |

## 8. 열린 질문

- 큰 창 안 인포박스에서 지금처럼 편집이나 폼 전환 같은 조작이 필요한가, 읽기 전용이면 충분한가. (M2 시작 때 인포박스 기능을 보고 제안)
