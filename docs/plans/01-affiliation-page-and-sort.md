## 1. 요청과 배경

| 요청(원문) | 결정 |
|---|---|
| "https://octinfo.shqjt.org/ 이 사이트를 봤을 때, 갈피 작품 페이지에 추가할 기능 같은 거 뭐 없을까." | 사이트(기관 페이지에 직급표와 소속 인물이 서열 순으로 모여 있는 구성)를 보고 6가지를 제안했다 |
| "네 제안대로 진행" | 제안한 추천안 1번(소속 페이지)과 2번(속성값 정렬)을 구현한다. 3~6번은 이후 |

한 줄 정의: 캐릭터의 `소속` 값을 같은 이름의 하위 문서로 이어 주고, 그 문서에 소속 인물을 자동으로 모아 보여 주며, 캐릭터 목록과 소속 인물 목록을 `서열` 같은 속성값으로 정렬할 수 있게 한다.

## 2. 목표와 비목표

- 목표
  - 정보 상자와 카드의 `소속` 값을 누르면 같은 제목의 하위 문서로 이동한다.
  - 그 하위 문서 아래에 "소속 인물" 카드 목록이 자동으로 나온다. 카드를 누르면 작품 페이지에서 그 캐릭터가 선택된다.
  - 캐릭터 그리드에 "정렬" 선택(수동 / 속성값 오름차순 / 내림차순)을 둔다. 소속 인물 목록도 같은 정렬을 따른다. 선택은 작품별로 저장한다.
- 비목표(지금 하지 않음)
  - 새 문서 종류(조직 전용 문서)와 새 DB 컬럼. 기존 하위 문서와 이름이 같으면 연결하는 방식만 쓴다.
  - 등급 배지, 기밀 표시, 소속 칩 필터, 공개용 내보내기(제안 3~6번).
  - 직급표 자동 생성. 직급표는 문서 본문(마크다운 표)에 직접 쓴다.
  - 백엔드 변경.

## 3. 현재 상태·조사

- (코드를 읽어 확인함) 캐릭터 객체에는 속성 값이 합쳐져 있어(`{...c, ...dp}`) `c['소속']`으로 읽는다. 속성 이름 목록은 `_propOrder`에 저장된다.
- (확인함) 소속 값은 쉼표로 여러 개를 쓸 수 있고, `*`로 시작하는 값은 그룹 분류에서 제외된다.
- (확인함) 하위 문서는 `wikiPages`(제목, 내용, parentId)이고 `/work/ID?pageId=문서ID`로 연다. 지금은 `소속` 값이 그냥 글자다.
- (확인함) 그룹 안 정렬은 `dp._groupSortOrders`(드래그로 정한 수동 순서)이고 속성값 정렬은 없다.
- (확인함) `[[이름]]` 링크 이동은 2026-10-22에 추가됐다(`backlink.js`). 이름 비교 규칙(`normalizeName`)을 재사용한다.

## 4. 설계와 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 연결은 "소속 값 = 하위 문서 제목"(공백·대소문자 무시)으로 한다 | 새 데이터 구조가 없고 백엔드 변경이 없다 | 조직 전용 문서 종류: 마이그레이션과 편집기 변경이 커서 이번에는 보류 |
| 소속 값에서 `*`로 시작하는 것은 링크와 인물 목록에서 뺀다 | 그룹 분류와 같은 규칙으로 일관 | `*`도 포함: 기존 의미가 불명확 |
| 숨김 캐릭터는 인물 목록에서 뺀다 | 카드 그리드와 같은 규칙 | - |
| 정렬 값 비교: 둘 다 숫자가 들어 있으면 처음 나오는 숫자로, 아니면 가나다순. 값이 없는 캐릭터는 방향과 무관하게 맨 뒤 | "서열 4", "22세", "3학년" 같은 값을 자연스럽게 정렬 | 문자열만 비교: "10"이 "9"보다 앞섬 |
| 정렬을 켜면 카드 드래그(수동 순서 변경)를 끈다 | 화면 순서와 저장되는 수동 순서가 어긋나 혼란 | 드래그 허용: 드래그해도 화면이 안 바뀜 |
| 정렬 선택은 `localStorage`의 작품별 키에 저장 | 분류 기준과 같은 방식 | 서버 저장: 작품 설정 변경이 됨 |
| 인물 카드는 `?charId=ID`로 작품 페이지를 열어 선택한다 | 주소만으로 상태를 복원, 새 상태 저장소 불필요 | 모달: 정보 상자와 이중 구현 |

## 6. 검증 방침

- 테스트: 정렬·소속 순수 함수의 경계값(빈 값, 숫자와 글자 혼합, `*`, 숨김, 공백), 상태 훅의 저장·복원, 컴포넌트(그리드 선택·링크·드래그 끔, 정보 상자 링크, 인물 목록), 작품 페이지 연결. 각 단계에서 연결을 되돌리는 변이 검사.
- 눈으로 확인: 라이트/다크 모드에서 링크 색 대비. 백엔드를 띄우지 않으면 실제 작품 페이지는 못 본다(그 경우 보고서에 명시).
- 수락 기준: 전체 테스트 통과, exe 재빌드 성공.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 소속 값과 문서 제목이 우연히 같아 의도 없이 링크가 걸림 | 링크일 뿐 동작은 이동이라 해가 작다. 문서에 링크 스타일로만 표시 |
| 같은 제목의 문서가 여러 개 | 먼저 나오는 문서로 연결 |
| 카드 안 링크 클릭이 카드 선택까지 일으킴 | 링크 클릭에서 이벤트 전파를 막고 테스트로 확인 |
| 값이 큰 작품에서 정렬이 느림 | 캐릭터 수십~수백 개 수준이라 영향 없음(추정, 미측정) |
