## 2. 목표와 비목표

- 목표
  - 창을 어떤 폭으로 늘려도 양옆이 비지 않고, 배경과 장르 테마가 가장자리까지 이어진다.
  - 본문(글)은 읽기 좋은 폭을 유지하고, 남는 폭은 패널과 여백이 쓴다.
  - 왼쪽 문서 트리, 오른쪽 목차(와 정보 상자)가 기본으로 보인다. 접고 펼 수 있고 고른 상태가 저장된다.
  - 맨 위 메뉴 바에서 새 작품, 수정, 내보내기, 패널 켜고 끄기, 다크 모드, 환경 설정을 한 곳에서 한다. 현재 화면에 없는 항목은 흐리게 보인다.
  - 라이트와 다크에서 모두 어색하지 않다.
- 비목표(지금 하지 않음)
  - Electron 기본 메뉴 사용. 웹에서도 같은 모양이어야 하므로 앱 안 메뉴로 만든다.
  - 메모 기능을 별도 화면으로 쪼개기, 하위 문서 자동 생성, 긴 문서 접기: 다음 단계(3단계)에서 다룬다.
  - 백업, 내장 DB: 4단계.
  - 이미 접근 가능한 기능의 위치를 대폭 바꾸는 것(현재 Gnb의 검색, 아이콘 버튼은 유지).
  - 편집기, 일괄 편집, 메모 화면의 전체 개편(이 화면들은 이미 100% 폭이다. 메뉴 바만 맞춘다).

## 3. 현재 상태·조사

- `App.jsx`: 앱 최상위 `div.galpi-app` 이 `maxWidth` 를 `layoutWidth === 'full' ? '100%' : '1200px'`, `margin: 0 auto` 로 잡는다. 편집기, 일괄, 메모 화면만 예외로 100%. 기본값 `layoutWidth: 'center'`(`useSettingStore`)라서 평소에는 1200px 가운데 칸이다. 설정 창에 "폭" 선택이 이미 있지만 기본이 좁은 쪽이다.
- 작품 페이지: `#galpi-genre-zone` 이 `wiki-container fixed-container`(max-width 1200px, 가운데)이고 장르 테마 CSS(`[data-genre-theme]`)는 이 안에서만 적용된다. 그래서 창을 넓히면 칸 바깥은 테마 없는 기본 배경이다(사용자가 본 "양옆 공백에 css가 안 먹음").
- 작품 페이지 안쪽: `wikiContentWrapper`(flex, gap 30) 안에 `wikiMain`(본문)과 `wikiAside`(정보 상자 340px).
- 양옆 패널: `FloatingLeftTree`(왼쪽 문서 트리)와 `FloatingToc`(오른쪽 목차)는 `position: fixed` 에 평소엔 32px 손잡이만 남기고 숨는다(마우스를 대야 펼쳐짐). `z-index: 10000`.
- 맨 위: `Gnb`(높이 60px: 로고, 검색, 설정, 팔레트, 다크, 새 작품 등록). 메뉴 바는 없다.
- 맨 아래: `Footer` 는 `position: fixed`, 높이 48px, `z-index: 8000`. 앱은 아래 48px 를 비워 둔다(`paddingBottom`).
- 다른 화면: 분류 페이지는 `min-width: 1200px; max-width: 1600px`. 홈은 `fixed-container`(max 1200px) 안.
- 캐릭터 큰 모달은 포털과 `position: fixed` 이므로 틀과 무관하다. 단 푸터 높이(52px) 보정은 유지해야 한다.

## 4. 설계와 결정

사용자와 합의(권장안)한 값은 "확정", 아직 시안으로 확인할 값은 "가정"으로 적는다.

| 결정 | 이유 | 버린 대안 | 구분 |
|---|---|---|---|
| 앱 폭 기본값을 `full`(창 전체)로 하고, 설정 창에는 "본문 폭 제한(1200px)" 선택을 남긴다. 저장소 버전을 올려 옛 `center` 저장값은 한 번만 `full` 로 바꾼다 | 기본이 좁으면 새로 안 열어 본 사람은 계속 웹처럼 보인다. 단 사용자가 고른 값을 몰래 바꾸지 않도록 마이그레이션은 한 번만 하고 이후 선택은 존중한다 | 설정 선택을 없앰(좁게 쓰고 싶을 때 방법 없음) | 확정 |

## 6. 검증 방침

- 테스트 먼저(jsdom 은 레이아웃을 계산하지 못하므로 동작과 클래스, 저장 상태를 확인한다)
  - 설정 저장소: 기본값, 마이그레이션(옛 `center` 가 한 번만 `full` 로, 이후 `center` 선택은 유지), 패널 상태 저장.
  - 메뉴 바: 역할 속성, 클릭으로 열고 닫기, 방향키, Enter, Esc, 화면별 활성 조건, 항목이 기존 함수를 호출하는지.
  - 패널: 열림/접힘 전환, 좁은 폭 상태에서 접힘(창 폭 값을 주입해 시험).
  - 작품 페이지: 3열 구조와 테마 영역 클래스가 새 규칙을 따르는지.
- 변이 검사: 마이그레이션 조건, 메뉴 활성 조건, 접힘 기준 폭.
- 화면 확인: 백엔드(실제 DB)가 있어야 작품 페이지가 뜨므로, 사용자가 쓰는 개발 서버 화면(`localhost:9691`)을 같이 보며 두 모드, 전체 화면, 반쪽 창을 확인한다. 작품 관련 시험은 "테스트" 작품(`/work/15`)에서만 한다.

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 테마 CSS 가 `.fixed-container`(1200px) 를 전제로 쓰여 있어 폭을 풀면 깨짐 | M1 에서 테마별로 확인하고, 깨지는 규칙은 `#galpi-genre-zone` 기준으로 고친다. 가로 스크롤(`contain: paint` 처리했던 고정 요소)이 다시 생기지 않는지 본다 |
| 고정 열이 본문을 좁혀 캐릭터 그리드 칸 수가 줄어듦 | 열 폭을 고정하고 좁은 창에서 접는다. 그리드는 칸 수가 폭에 따라 자동으로 바뀌는지 확인 |
| 모달, 푸터와 z-index 충돌(큰 캐릭터 모달 아래쪽 가림 문제가 있었음) | 푸터 보정(52px)을 유지하고 메뉴 드롭다운은 모달보다 낮게 둔다. 테스트로 고정 |
| 폭 기본값 변경이 이미 쓰는 사람(사용자 본인)에게 갑작스러움 | 설정에 되돌리는 선택을 남기고, CHANGELOG 에 변경을 분명히 적는다 |
| 한 번에 너무 많이 바꿈 | M1~M4 로 쪼개고 각 단계마다 확인 |
| 메뉴 동작이 기존 버튼과 어긋나 두 벌이 됨 | 메뉴는 기존 함수를 그대로 부르고 새 로직을 만들지 않는다 |

## 8. 후속 단계(이 계획서 밖, 합의된 순서)

- 3단계: 새 소속 값을 쓰면 하위 문서 자동 생성, 긴 문서 보기(제목별 접기, 읽기 폭, 현재 위치를 보여 주는 고정 목차).
- 4단계: 백업(작품 내보내기 zip + DB 덤프), 내장 DB/이식성, `ARCHITECTURE.md` 의 exe DB 설명 바로잡기.
- 메모 기능을 메뉴가 생긴 뒤 별도 화면으로 분리할지 판단.
