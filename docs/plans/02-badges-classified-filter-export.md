## 1. 요청과 배경

| 요청(원문) | 결정 |
|---|---|
| "그럼 새로 작품 페이지 만들고 캐릭터 넣고. 소속값이 생길 때마다 하위 문서가 자동으로 생기도록 할 수 있는지? 그거 확인하고 다음 3, 4, 5, 6 진행" | 자동 생성은 가능 여부를 조사해 보고한다(구현은 하지 않음, 7장). 3~6번(등급 배지, 기밀 표시, 소속 칩 필터, 공개용 내보내기)을 구현한다 |

한 줄 정의: octinfo 사이트(기관 페이지, 등급표, 기밀 도장, 정적 공개)에서 가져온 아이디어 4가지를 갈피 작품 페이지에 붙인다.

## 2. 목표와 비목표

- 목표
  - 3 등급 배지: 작품마다 등급 속성(예: 위험도 R, 유용성 U)과 0~5 기준표를 정해 두면 카드와 정보 상자에 작은 배지로 보이고, 작품 페이지에 기준표가 나온다.
  - 4 기밀 표시: `기밀` 속성이 켜진 캐릭터에 "기밀" 도장을 붙이고, "기밀 가리기"를 켜면 사진과 내용을 흐리게 가렸다가 눌러서 연다.
  - 5 소속 칩 필터: 캐릭터 목록 위에 소속(과 등급)별 칩을 두고 눌러서 걸러 본다.
  - 6 공개용 내보내기: 작품 페이지를 읽기 전용 단일 HTML 파일로 내려받는다.
- 비목표(지금 하지 않음)
  - 내보낸 페이지에 장르 테마 CSS 적용(테마가 앱 전역 변수에 기대고 있어 따로 큰 작업). 라이트/다크 자동 전환만 지원.
  - 소속 값이 생길 때 하위 문서 자동 생성(7장에 조사 결과만).
  - 백엔드 변경과 새 DB 컬럼. 모든 설정은 작품 설명 메타(`META_DATA`)와 캐릭터 속성에 저장한다.
  - 내보낸 파일의 호스팅과 업로드(사용자가 직접 올린다).

## 3. 현재 상태·조사

- (코드를 읽어 확인함) 작품 설정은 설명 첫 줄 `[META_DATA:{...}]`에 JSON으로 저장되고, 편집기는 모르는 키를 그대로 보존한다(`originalMeta` 펼침).
- (확인함) 그룹 순서(`_groupOrder`)는 편집기 텍스트칸 -> 메타 JSON으로 저장하는 선례가 있다(`WorkMetaPanel`, `useEditorFetch`, `useEditorSave`).
- (확인함) 캐릭터 속성은 자유 이름의 속성이라 `기밀`, `위험도` 같은 속성을 편집기와 일괄 편집에서 이미 추가할 수 있다.
- (확인함) 마크다운은 `renderMarkdown`(`utils/markdown/coreRenderer`)과 `MarkdownRenderer.jsx`가 HTML로 바꾼다. 로그탭, 타임라인 등 매크로는 인라인 스타일이라 내보내기에 그대로 쓸 수 있다.
- (확인함) 캐릭터 이미지는 `/img/character/작품명_이름.확장자`, 커버는 `/img/cover/작품명.확장자`이다(Galpi-Media).
- (추정, 미확인) 내보내기에서 이미지를 data URI로 넣을 때 축소(폭 360px, webp)하면 캐릭터 50명에 약 1~2MB.

## 4. 설계와 결정

| 결정 | 이유 | 버린 대안 |
|---|---|---|
| 3: 등급 설정은 메타의 `ratingAxes`("속성이름:약칭" 줄), `ratingScale`("등급:명칭:기준" 줄) 문자열 | 편집기 텍스트칸 한 줄씩이라 입력이 쉽고 파싱 실패해도 문자열이 남음 | 배열 JSON: 편집 UI가 커짐 |
| 3: 배지는 약칭+숫자 칩, 색은 점으로만 표시하고 글자색은 부모를 따름 | 장르 테마의 글자색을 덮지 않아 어두운 테마에서도 읽힘 | 등급별 배경색 칩: 테마별 대비 문제 |
| 3: 등급 값이 기준표에 없는 숫자면 배지는 숫자만 보이고 툴팁에 명칭이 없음 | 입력 오류에도 화면이 깨지지 않음 | - |
| 4: 기밀 여부는 `기밀` 속성 값(비어 있지 않고 아니오/N/false/0/x가 아님)으로 판단 | 새 편집 UI 없이 기존 속성 입력으로 가능 | 전용 체크박스: 편집기와 일괄 편집을 모두 고쳐야 함 |
| 4: 도장은 항상 보이고, 가림(흐림)은 "기밀 가리기" 켠 때만. 기본은 꺼짐, 작품별 저장 | 작성자는 평소 다 보고 싶고, 공개용 열람에서만 가림 | 기본 켜짐: 편집 중 불편 |
| 4: 가려진 카드를 누르면 그 카드만 열림(새로고침 시 다시 가림) | 실수로 노출되지 않게 | 영구 해제 저장: 가림의 의미 약화 |
| 5: 칩은 `소속`, `등급` 속성 두 그룹. 그룹 안은 OR, 그룹 사이는 AND. 선택은 저장하지 않음 | 조직별 보기가 핵심, 상태 저장은 불필요 | 모든 속성 칩: 칩이 너무 많아짐 |
| 6: 클라이언트에서 단일 HTML을 만들어 내려받기(`작품명.html`). 이미지는 축소해 data URI로 포함 | 서버 변경과 압축 라이브러리 없이 한 파일로 공유 가능 | ZIP+상대 이미지: 압축 라이브러리 추가 필요 |
| 6: 내보내기에서 숨김 캐릭터는 항상 제외, 기밀 캐릭터는 "제외 / 도장만 남기고 내용 숨김 / 그대로" 선택(기본: 내용 숨김) | 공개용에서 기밀이 새지 않게 | 항상 포함: 기밀의 의미 상실 |
| 6: 장르 테마는 제외하고 자체 간단한 스타일(라이트/다크 자동) | 테마 CSS는 앱 전역 변수에 의존 | 테마 포함: 별도 큰 작업 |

## 6. 검증 방침

- 테스트: 각 순수 함수의 경계값, 컴포넌트 동작, 작품 페이지 연결, 연결을 되돌리는 변이 검사. 내보내기 HTML은 문자열 구조와 기밀 옵션별 포함 여부를 검사한다.
- 눈으로 확인: 라이트/다크, 어두운 장르 테마에서 배지 글자 대비. 백엔드를 띄우지 않으면 실제 화면은 못 보고 그 사실을 보고서에 쓴다.
- 수락 기준: 전체 테스트 통과, exe 재빌드 성공.

## 7. 조사: 소속 값이 생길 때 하위 문서 자동 생성

- 가능하다. 문서 생성 API(`POST /api/wikipages`)는 제목, 작품 번호, 상위 문서 번호만 받는다. 소속 값 중 같은 제목의 문서가 없는 것(`organization.js`의 규칙 재사용)을 찾아 만들면 된다.
- 만드는 시점 후보
  1. 캐릭터 저장 직후(편집기)와 일괄 편집 저장 직후에 자동 생성.
  2. 작품 페이지에 "문서가 없는 소속 N개 [문서 만들기]" 안내를 띄우고 버튼으로 한꺼번에 생성.
  3. 서버(`CharacterController` 저장)에서 생성.
- 위험: 일괄 편집은 요청이 동시에 많이 날아가 같은 소속 문서가 중복 생성될 수 있다. 오타가 쓰레기 문서를 만든다. 사용자가 지운 문서가 저장할 때마다 되살아난다. 서버 방식은 백엔드 수정과 exe 백엔드 재빌드가 필요하다.
- 권장: 2번(안내 + 버튼). 사용자가 확인한 뒤 한 번에 만들어 중복, 오타 문제가 없고 백엔드 변경이 없다. 이번 범위에는 넣지 않았다.

## 8. 열린 질문

- 소속 문서 자동 생성을 2번 방식으로 할지(사용자 결정 대기).
- 내보내기에 장르 테마를 넣을지(별도 계획).
