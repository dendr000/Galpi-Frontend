# 문서 트리와 새 문서 만들기

> 대상 파일: `src/domains/work/FloatingLeftTree.jsx`, `TreeContextMenu.jsx`, `newPageUrl.js`, `src/pages/WorkDetail/WorkDetailPage.jsx` / 추가: 2026-10-26

## 무엇을 하나

하위 문서를 만들 때마다 작품 첫 화면으로 돌아가 "새 문서 추가"를 누르던 과정을 없앤다. 문서 어디에서든 바로 새 문서를 만들고, 문서 트리에서 작품 첫 화면으로도 한 번에 돌아간다.

## 사용법

| 상황 | 방법 |
|---|---|
| 지금 보는 문서와 **같은 위치**(같은 상위 문서 아래)에 새 문서 | 하위 문서 화면의 "+ 같은 위치에 새 문서" 버튼, 또는 트리에서 그 문서 우클릭 > "같은 위치에 문서 만들기" |
| 어떤 문서의 **하위 문서** 만들기 | 트리에서 그 문서 우클릭 > "하위 문서 만들기" (문서 화면의 "+ 새 문서 추가"도 지금 문서의 하위 문서를 만든다) |
| **최상위 문서** 만들기 | 트리에서 작품 이름 행이나 빈 곳 우클릭 > "최상위 문서 만들기" |
| **작품 첫 화면**으로 돌아가기 | 트리 맨 위의 작품 이름 행을 누른다 |

## 규칙

- 최상위 문서의 "같은 위치"는 최상위 문서다(상위 문서 없음).
- 우클릭 메뉴는 Esc 를 누르거나 바깥을 누르면 닫히고, 항목을 고르면 닫힌다. 다른 문서를 우클릭하면 메뉴가 그 문서 기준으로 바뀐다.
- **Shift+우클릭은 앱 전체 메뉴가 쓰므로** 트리 메뉴는 열지 않는다.
- 트리 맨 위의 작품 이름 행은 작품 첫 화면에 있을 때 현재 위치(굵은 표시)로 보인다.
- 문서 트리는 화면 왼쪽 손잡이에 마우스를 올리면 펼쳐진다(기존 그대로).

## 용어

- **상위 문서(parentId)**: 어떤 문서가 속한 문서. 최상위 문서는 없다.
- **같은 위치(형제)**: 상위 문서가 같은 문서끼리의 관계.
- **포털**: 트리 패널의 움직임(옆에서 미끄러져 나옴) 때문에 메뉴 위치가 어긋나지 않도록 메뉴를 화면 바닥(body)에 직접 그리는 방식.

## 구조

- `newPageUrl.js`: 새 문서 편집 주소와 "같은 위치"의 상위 문서 번호(순수 함수).
- `TreeContextMenu.jsx`: 우클릭 메뉴. `FloatingLeftTree.jsx`: 작품 이름 행, 문서 우클릭 메뉴 연결.
- `WorkDetailPage.jsx`: "같은 위치에 새 문서" 버튼, 트리에 작품 제목 전달. `SubPageList.jsx` 도 같은 주소 함수를 쓴다.

## 검증

`npm test`: 주소 계산(상위 유무, 최상위), 트리(작품 이름 행 이동과 현재 위치 표시, 우클릭 세 항목의 이동 주소, 닫힘, Shift+우클릭 제외, 빈 작품), 작품 페이지(버튼 표시와 이동, 기존 "새 문서 추가" 유지, 트리 연결). 연결을 되돌리면 18개가 실패하는 것을 확인했다. 브라우저에서 실제 CSS 로 트리를 올려 메뉴 위치와 항목, "같은 위치" 선택 시 이동 주소를 확인했다. 마우스로 직접 우클릭해 보는 확인은 이 환경의 호버 에뮬레이션 한계로 못 했고(이벤트를 코드로 보내 확인), 실제 작품 데이터로 앱을 열어 보지도 못했다.
