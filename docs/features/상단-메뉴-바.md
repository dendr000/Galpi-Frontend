# 상단 메뉴 바

> 대상 파일: `src/components/layout/menuBar/MenuBar.jsx`, `MenuBar.module.css`, `menuDefinitions.js`, `menuActions.js`, `src/components/layout/Gnb.jsx`, `src/App.jsx`, `src/pages/WorkDetail/WorkDetailPage.jsx`, `src/styles/global.css` / 추가: 2026-11-09 / 계획서: `docs/plans/05-app-shell.md` (M3)

## 무엇을 하나

화면 맨 위(상단 바 위)에 얇은 메뉴 바(높이 28px)를 둔다. **파일, 편집, 보기, 설정** 네 메뉴가 있고, 다른 프로그램의 메뉴처럼 눌러서 연다. Electron 기본 메뉴가 아니라 앱 안에서 그려서 웹과 exe 가 같은 모양이다.

메뉴는 지금 보고 있는 화면에 맞게 켜지고 꺼진다. 쓸 수 없는 항목은 흐리게 보이고 눌러도 아무 일도 하지 않는다.

| 메뉴 | 항목 | 쓸 수 있는 때 |
|---|---|---|
| 파일 | 새 작품 | 언제나 |
| | 새 문서, 새 캐릭터, 일괄 편집 | 작품 페이지 |
| | 공개용 HTML 내보내기 | 작품 첫 화면(하위 문서를 보는 중에는 쓸 수 없음) |
| 편집 | 이 작품 수정 | 작품 페이지 |
| | 이 문서 수정 | 작품 페이지에서 하위 문서를 보는 중 |
| | 찾기 (Ctrl+F) | exe(앱) 에서만. 일반 브라우저는 브라우저 자체의 찾기를 쓴다 |
| 보기 | 왼쪽 패널 (문서 트리), 오른쪽 패널 (목차) | 작품 페이지. 체크 표시는 "붙여 둠" 상태 |
| | 본문 폭 제한 | 언제나. 체크하면 앱이 1200px 가운데 칸이 된다 |
| | 다크 모드 | 언제나. 체크 표시가 켜짐 |
| | 작품 테마 바꾸기 | 작품 페이지. 상단 바의 팔레트 버튼과 같은 동작 |
| 설정 | 환경 설정 | 언제나 |
| | 콘솔 로그 보기 | 언제나. 체크 표시가 켜짐(자세한 내용은 `콘솔-로그-켜고-끄기.md`) |

각 항목은 이미 있던 기능(버튼, 설정 값, 이동 주소)을 그대로 부른다. 메뉴만을 위한 새 동작은 만들지 않았다. 상단 바의 다크 모드와 팔레트 버튼도 같은 함수(`menuActions.js`)를 쓰도록 바꿔서 두 벌이 되지 않는다.

## 조작법

- **마우스**: 메뉴 이름을 누르면 열리고, 다시 누르면 닫힌다. 하나가 열려 있으면 다른 이름 위로 마우스만 가져가도 그 메뉴로 바뀐다. 메뉴 밖을 누르면 닫힌다. 항목을 고르면 실행되고 닫힌다.
- **키보드**: 메뉴 이름에서 `아래` / `Enter` / `Space` 로 열고(첫 항목으로 이동), `위` 는 마지막 항목으로 연다. 열린 메뉴에서 `위` `아래` 는 쓸 수 있는 항목만 돌고(끝에서 처음으로 이어짐), `Home` `End` 는 처음과 끝으로, `왼쪽` `오른쪽` 은 옆 메뉴로 간다. `Enter` / `Space` 는 실행, `Esc` 는 닫고 그 메뉴 이름으로 돌아오며, `Tab` 은 닫는다.
- 스크린 리더용 속성: 메뉴 바는 `menubar`, 열리는 목록은 `menu`, 항목은 `menuitem` (체크 항목은 `menuitemcheckbox` 와 `aria-checked`).

## 어디에 보이나

모든 화면(홈, 분류, 작품, 뷰어, 편집기, 일괄 편집, 메모)에 보인다. 편집기, 일괄 편집, 메모에는 상단 바가 없고 메뉴 바만 붙는다. 이 세 화면에서는 작업 중인 내용을 잃지 않도록 "새 작품"(다른 화면으로 이동)을 쓸 수 없고(흐리게 보임), 나머지 항목은 화면에 맞게 켜지고 꺼진다. 열린 목록의 겹침 순서는 큰 캐릭터 창(3000)보다 낮은 2500 이다.

## 스크롤할 때

메뉴 바와 상단 바는 스크롤해도 맨 위에 함께 붙어 있다(메뉴 바 0~28px, 상단 바 28~89px). 작품 페이지의 양옆 패널과 정보 상자, 편집기 머리글은 그 바로 아래(89px, 편집기는 28px)에서 멈춘다.

## 구조(개발자용)

- `menuDefinitions.js` — `buildMenus()` 가 메뉴 구성과 각 항목의 `disabled`, `checked`, `onSelect` 를 순수 함수로 만든다. 주소에서 작품 번호와 문서 번호를 읽는 `parseWorkRoute()` 포함. 화면 없이 시험한다.
- `menuActions.js` — 다크 모드 전환, 작품 테마 순환, 찾기 열기, 화면 안쪽 동작 알림(`dispatchMenuAction`)을 담은 공용 동작.
- `MenuBar.jsx` — 위 두 가지를 이용해 그리는 화면, 열림 상태, 키보드 처리.
- 작품 페이지의 내보내기 창은 그 페이지 안쪽 상태라서, 메뉴가 `galpi-menu-action` 이벤트(`export-work`)를 보내면 `WorkDetailPage` 가 받아 연다.
- 위아래 고정 영역 높이 변수 `--app-header-h` 가 61px 에서 89px(메뉴 바 28 + 상단 바 61)로 바뀌어, 작품 페이지 양옆 패널의 높이와 영역 최소 높이가 그에 맞춰진다.

## 용어

- **메뉴 바(menubar)**: 화면 맨 위에 가로로 늘어선 메뉴 이름 줄(파일, 편집 등).
- **체크 항목**: 켜짐과 꺼짐을 오가는 항목. 켜져 있으면 앞에 체크 표시가 보인다.
- **스크린 리더**: 화면을 소리로 읽어 주는 보조 프로그램. 역할 속성(`role`)을 보고 메뉴임을 안다.

## 아직 안 한 것

- 작업 중 화면(편집기, 일괄, 메모) 전용 항목(예: 저장하고 나가기)은 없다. 필요하면 다음에 추가한다.
- Alt+글자 단축 키(예: Alt+F 로 파일 메뉴 열기), 메뉴 항목의 하위 메뉴(시안의 "작품 테마 바꾸기" 화살표).

## 확인한 것

- 실제 브라우저(개발 서버)에서 메뉴 바만 따로 띄운 시험 화면으로 높이 28px, 열린 목록 겹침 순서 2500, 라이트와 다크 모두에서 보이고, 다크 모드 항목을 누르면 화면이 바뀌고 저장되며 다시 열면 체크 표시가 켜져 있음을 확인했다.
- 실제 작품 페이지에서의 모양(상단 바와의 간격, 양옆 패널 높이)은 백엔드가 필요해 사용자가 직접 확인해야 한다.
