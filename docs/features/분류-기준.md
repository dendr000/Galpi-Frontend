# 분류 기준 (캐릭터 그룹 묶기)

> 대상 파일: `src/domains/character/characterGroups.js`, `CharacterGrid.jsx`, `useCharacterDrag.js` / 변경: 2026-10-29

## 무엇을 하나

작품 페이지 "등장인물 목록" 위의 **분류 기준** 선택에서 고른 속성의 값으로 캐릭터를 그룹으로 묶는다. 예를 들어 `직책별`을 고르면 `기사`, `마법사` 같은 값마다 그룹이 생긴다.

## 선택 목록

| 순서 | 항목 |
|---|---|
| 앞 | 관계별, 소속별, 등급별, 종족별, 성별별 (속성이 없는 작품에서도 항상 있다) |
| 뒤 | 작품의 캐릭터들에 값이 있는 나머지 속성 전부(`서열별`, `나이별`, `직책별` 등). 정렬 선택 목록과 같은 속성들이고 처음 나온 순서대로 |

- 전에는 앞의 다섯 개만 고를 수 있었다.
- 예전에 저장해 둔 분류 기준이 지금은 없는 속성이어도 목록 끝에 남아 선택이 비지 않는다.
- 선택은 작품별로 이 PC에 저장되고, 공개용 HTML 내보내기도 같은 기준을 쓴다.

## 규칙

- 값이 쉼표로 여러 개면 "여러 값일 때 그룹 표시" 설정(`여러-값-그룹-표시.md`)에 따라 모든 값의 그룹, 첫 번째, 마지막 값의 그룹에 들어간다. `*`로 시작하는 값은 뺀다.
- 값이 없거나 `*`뿐이면 "미분류".
- `나이`, `성별`, `종족`처럼 전용 칸에 저장된 항목도 같은 방식으로 읽는다.
- 값이 모두 다른 속성(예: 서열 1, 2, 3...)을 고르면 값마다 그룹이 하나씩 생겨 그룹이 많아진다.
- 그룹 순서는 작품 편집의 "그룹 정렬 순서"(`속성명: 값1, 값2`)로 정할 수 있고, 어떤 속성이든 같은 방식이다. 정하지 않은 값은 뒤에 원래 순서로 온다.
- 카드를 끌어 순서를 바꿀 때도 화면에 보이는 그룹 구성원만 대상이다. 그룹 안 순서는 그룹 이름별로 저장되므로 서로 다른 분류 기준에 같은 이름의 값이 있으면 순서가 공유된다.

## 용어

- **분류 기준**: 캐릭터를 묶을 때 쓰는 속성 이름.
- **그룹 구성원 계산(`getGroupTags`)**: 캐릭터 한 명이 어느 그룹들에 들어갈지 정하는 함수. 화면과 카드 끌기가 같은 함수를 쓴다.

## 검증

`npm test`: 선택 목록 만들기(기본 다섯 개, 추가 속성, 중복 제거, 저장된 값 유지, 목록 없음), 그리드 선택칸(전체 속성 표시, 선택 시 호출, 없는 속성 유지), 그룹 구성원 계산(쉼표, `*`, 미분류, 첫 번째/마지막, 전용 필드), 직책·나이로 묶기, 카드 끌기(모드별 구성원). 변이 검사 3가지(끌기가 설정을 무시, 전용 필드를 못 읽음, 그리드가 속성 목록을 무시)에서 각각 테스트가 실패하는 것을 확인했다. 실제 화면은 백엔드를 띄우지 않아 보지 못했다.
