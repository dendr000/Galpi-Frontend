# 공개용 HTML 내보내기

> 대상 파일: `src/domains/work/export/*`, `src/pages/WorkDetail/WorkDetailPage.jsx` / 추가: 2026-10-22 / 계획서: `docs/plans/02-badges-classified-filter-export.md`

## 무엇을 하나

작품 페이지를 읽기 전용 HTML 파일 하나로 내려받는다. 파일 하나만 열면(인터넷 연결 없이도) 작품 소개와 인물이 그대로 보이므로, 다른 사람에게 보내거나 직접 웹에 올려 공개할 수 있다. (이 기능은 octinfo 사이트처럼 정적 페이지로 공개하는 용도에서 아이디어를 가져왔다.)

## 사용법

1. 작품 첫 화면의 오른쪽 위 "공개용 HTML 내보내기" 버튼을 누른다.
2. 옵션을 고르고 "내보내기"를 누른다.
   - **기밀 캐릭터**(기밀 캐릭터가 있을 때만 보임): 가림(이름과 도장만 남김, 기본) / 제외 / 그대로
   - **이미지 포함**(기본 켜짐): 사진을 폭 420px로 줄여 파일에 담는다. 끄면 이미지 없이 가벼운 파일이 된다.
   - **하위 문서 포함**(기본 켜짐)
3. `작품 제목.html` 파일이 내려받아진다(exe에서는 저장 창이 뜬다).

## 담기는 내용

- 대문 이미지, 제목, 제작자, 분류, 상태, 내보낸 날짜
- 개요, 설정(마크다운과 매크로: 게이지, 로그탭, 타임라인, 관계도, 스탯 등)
- 등급 기준표(설정한 경우)
- 등장인물: 지금 화면의 분류 기준과 정렬대로 묶은 카드(사진, 속성 표, 등급 배지, 상세 설정 접기). 같은 인물이 여러 그룹에 속하면 각 그룹에 나오지만 링크는 첫 카드로 간다.
- 하위 문서와 그 문서 제목과 같은 소속의 인물 링크

## 규칙

- **숨김 캐릭터는 항상 빠진다.** 칩 필터는 적용되지 않는다(전체가 나감).
- **기밀 처리는 인물 카드에만 적용된다.** 가림이면 속성, 사진, 상세, 등급 배지를 아예 데이터에 담지 않는다(파일을 열어 소스를 봐도 없다). 개요, 설정, 문서 본문에 직접 쓴 내용은 그대로 나간다. 이 점을 옵션 창에도 안내한다.
- **안전:** 본문에 직접 쓴 `<script>`, `<iframe>` 같은 태그, `onclick` 같은 이벤트 속성, `javascript:` 주소는 제거된다. 모든 이름과 값은 이스케이프된다. 파일은 외부 스크립트나 스타일시트를 불러오지 않는다.
- 스포일러는 이벤트 대신 CSS 호버(마우스를 올리면 보임)로 동작한다.
- 라이트/다크는 보는 사람의 브라우저 설정(`prefers-color-scheme`)을 따른다.
- **장르 테마는 적용되지 않는다**(테마 CSS가 앱 전역 변수에 기대고 있음).
- 이미지를 불러오지 못한 인물은 사진만 빠진 채 계속 만든다. 만들기에 실패하면 창에 오류가 뜨고 닫히지 않는다.
- 서버 호출이나 저장은 없다. 전부 이 화면에서 만들어 내려받는다.

## 용어

- **단일 파일(정적 HTML)**: 서버 없이 브라우저로 바로 열 수 있는 파일.
- **데이터 주소(data URI)**: 이미지를 글자로 바꿔 HTML 안에 직접 넣는 방식. 별도 이미지 파일이 필요 없다.
- **정화(sanitize)**: 위험한 코드를 제거해 안전하게 만드는 처리.
- **이스케이프**: `<` 같은 글자를 화면 글자로만 보이게 바꾸는 처리.

## 구조

- `prepareExportModel.js`: 보이는 캐릭터와 그룹, 기밀 처리, 이미지, 본문 변환으로 내보낼 데이터를 준비한다.
- `exportHtml.js`, `exportStyles.js`: 데이터로 HTML 문서와 스타일을 조립한다.
- `sanitizeExportHtml.js`, `inlineImages.js`, `imageToDataUri.js`: 본문 정화와 이미지 담기.
- `exportWork.js`, `useWorkExport.js`, `downloadFile.js`, `ExportDialog.jsx`: 실행, 내려받기, 옵션 창.
- 공유 부품: `characterGroups.js`(그룹 계산), `renderMarkdownHtml.js`(마크다운 변환). 작품 페이지 화면과 같은 코드를 쓴다.

## 검증

`npm test`: 문서 조립(이스케이프, 구역 유무, 중복 id, 외부 참조 없음), 데이터 준비(기밀 세 가지 처리, 이미지 옵션, 숨김, 속성 표 규칙, 문서와 소속 인물), 정화, 이미지 담기와 축소, 옵션 창, 작품 페이지 연결. 작품 페이지 연결을 되돌리면 5개가 실패하는 것을 확인했다. 브라우저에서 샘플 데이터로 실제 생성해 렌더링해 보았다(다크 모드: 개요 게이지, 로그탭, 가림 카드, 등급 배지, 속성 정렬 확인). 실제 작품 데이터와 exe 저장 창은 확인하지 못했다.
