# 페이지 찾기 (Ctrl+F)

> 대상 파일: `src/components/common/FindBar.jsx`, `src/components/common/findInPage.js`, `src/App.jsx` / 추가: 2026-10-22, 엔진 교체: 2026-10-26

## 무엇을 하나

갈피 데스크톱 앱(exe)에서 Ctrl+F를 누르면 오른쪽 위에 찾기창이 뜨고, 지금 보고 있는 페이지 안의 글자를 찾아 표시한다. 작품 페이지처럼 긴 문서에서 인물 이름이나 설정을 빠르게 찾는 용도다.

## 왜 필요했나

크롬 같은 브라우저에는 Ctrl+F 찾기 창이 기본으로 있지만, exe의 화면 엔진(Electron)에는 없어서 Ctrl+F가 아무 일도 하지 않았다. 일반 브라우저(`npm run dev`)에서는 원래 됐다.

## 사용법

| 조작 | 동작 |
|---|---|
| Ctrl+F (맥은 Cmd+F) | 찾기창을 연다. 짧은 글자를 선택해 둔 상태면 그 글자가 미리 채워진다 |
| 글자 입력 | 입력하는 대로(한글 조합 중에도) 찾아 모든 일치를 노랑, 현재 일치를 주황으로 표시하고 그 위치로 스크롤한다 |
| Enter / F3 / "다음" | 다음 일치로 이동(끝에서는 처음으로 돌아감) |
| Shift+Enter / Shift+F3 / "이전" | 이전 일치로 이동 |
| Esc / "닫기" | 찾기창을 닫는다(표시된 글자는 그대로) |

찾으면 "1 / 3"처럼 현재 번호와 전체 개수가 보이고, 없는 글자는 "찾는 글자가 없습니다"가 나온다. '라' 같은 한 글자도 찾는다. 한글을 조합하는 중의 Enter는 찾기로 보지 않는다.

## 규칙

- **exe에서만 켜진다.** 사용자 에이전트에 `Electron`이 있을 때만 동작하고, 일반 브라우저에서는 브라우저 기본 찾기를 그대로 쓴다.
- **에디터는 기존 에디터 찾기가 우선한다.** 에디터 찾기가 먼저 Ctrl+F를 처리하면(기본 동작을 막으면) 이 찾기창은 열지 않는다.
- 대소문자는 구분하지 않고, 앞뒤 공백은 무시한다. 찾기창 자신과 보이지 않는 요소(display:none, hidden), 입력칸 값은 찾지 않는다.
- 글자 노드 하나 안에서만 찾는다. 굵게 등으로 나뉜 글자에 걸친 검색어는 찾지 못할 수 있다.
- 찾는 동안 입력칸의 포커스와 문서의 선택은 건드리지 않는다. (예전에는 `window.find` 가 입력칸 자신에 걸려 찾기창을 숨겼고, 그 탓에 한글 조합이 끊겼다. `docs/troubleshooting.md` 2026-10-26 참고)

## 용어

- **Electron**: 웹 화면으로 데스크톱 앱을 만드는 도구. exe의 화면 엔진이다.
- **CSS Highlight**: 문서의 선택이나 포커스를 바꾸지 않고 글자 범위에 배경색을 입히는 브라우저 기능(`::highlight`).
- **Range**: 문서 안의 글자 구간을 가리키는 객체. 일치한 곳마다 하나씩 만든다.
- **IME 조합**: 한글처럼 여러 키를 눌러 한 글자를 만드는 입력 방식. 조합 중에는 Enter가 글자 확정에 쓰인다.

## 검증

`npm test`: 엔진(`findInPage.test.js`: 한 글자 한글, 여러 일치, 대소문자, 제외 요소, 숨김·script·입력칸 제외, 공백·NFC, 표시 지우기)과 찾기창(`FindBar.test.jsx`: 열고 닫기, 이동, '강소라'를 자모부터 조합하며 입력해도 포커스 유지, 한 글자 검색, 조합 중 Enter, 선택 글자 미리 채움). 변이 검사로 "검색어가 바뀌어도 다시 찾지 않음"과 "한 글자 검색 막음"을 넣으면 각각 10개, 12개가 실패함을 확인했다. 실제 브라우저(Chrome 엔진)에서 엔진을 불러 '라' 2개, '소' 2개, '강소라' 1개 일치와 CSS Highlight 표시를 확인했다. 실제 한글 IME 입력과 exe 에서의 동작은 자동으로 확인하지 못했다.
