# 페이지 찾기 (Ctrl+F)

> 대상 파일: `src/components/common/FindBar.jsx`, `src/App.jsx` / 추가: 2026-10-22

## 무엇을 하나

갈피 데스크톱 앱(exe)에서 Ctrl+F를 누르면 오른쪽 위에 찾기창이 뜨고, 지금 보고 있는 페이지 안의 글자를 찾아 표시한다. 작품 페이지처럼 긴 문서에서 인물 이름이나 설정을 빠르게 찾는 용도다.

## 왜 필요했나

크롬 같은 브라우저에는 Ctrl+F 찾기 창이 기본으로 있지만, exe의 화면 엔진(Electron)에는 없어서 Ctrl+F가 아무 일도 하지 않았다. 일반 브라우저(`npm run dev`)에서는 원래 됐다.

## 사용법

| 조작 | 동작 |
|---|---|
| Ctrl+F (맥은 Cmd+F) | 찾기창을 연다. 짧은 글자를 선택해 둔 상태면 그 글자가 미리 채워진다 |
| 글자 입력 | 입력하는 대로 찾아 해당 글자를 표시하고 그 위치로 스크롤한다 |
| Enter / F3 / "다음" | 다음 일치로 이동(끝에서는 처음으로 돌아감) |
| Shift+Enter / Shift+F3 / "이전" | 이전 일치로 이동 |
| Esc / "닫기" | 찾기창을 닫는다(표시된 글자는 그대로) |

없는 글자를 찾으면 "찾는 글자가 없습니다"가 나온다. 한글을 조합하는 중의 Enter는 찾기로 보지 않는다.

## 규칙

- **exe에서만 켜진다.** 사용자 에이전트에 `Electron`이 있을 때만 동작하고, 일반 브라우저에서는 브라우저 기본 찾기를 그대로 쓴다.
- **에디터는 기존 에디터 찾기가 우선한다.** 에디터 찾기가 먼저 Ctrl+F를 처리하면(기본 동작을 막으면) 이 찾기창은 열지 않는다.
- 대소문자는 구분하지 않는다. 현재 일치 부분만 표시한다(전체 일치 개수나 모든 일치 강조는 없다).
- 찾는 동안에는 찾기창을 잠깐 숨긴다. 브라우저 찾기가 입력칸 안의 글자도 검색해서 입력칸 자신에 걸리는 문제를 막기 위해서다.

## 용어

- **Electron**: 웹 화면으로 데스크톱 앱을 만드는 도구. exe의 화면 엔진이다.
- **`window.find`**: 브라우저가 가진 "페이지에서 글자 찾기" 기능을 코드에서 부르는 함수.
- **IME 조합**: 한글처럼 여러 키를 눌러 한 글자를 만드는 입력 방식. 조합 중에는 Enter가 글자 확정에 쓰인다.

## 검증

`npm test`: 열고 닫기(Ctrl+F, Cmd+F, Esc, 닫기, 이미 열린 상태, 꺼진 환경, 에디터가 먼저 처리한 경우), 찾기(Enter, Shift+Enter, F3, 입력하는 대로, 빈 입력, 조합 중, 못 찾음 안내, 버튼), 찾는 동안 숨김과 포커스 복귀. 브라우저 엔진에서 실제 `window.find`로 키 입력 확인(열림, 표시, 스크롤, 없는 글자 안내, Esc)했다. 이때 입력칸 자신이 검색에 걸려 "찾았다"고 나오는 문제를 발견해 고쳤다. `App.jsx`에 달았다는 연결 자체는 테스트가 없고, 실제 exe에서는 아직 확인하지 못했다.
