# 문제 해결 기록

## 2026-10-23 좁은 창에서 등장인물 목록 머리말이 글자 단위로 줄바꿈된다

- **증상**: 화면을 반으로 나눠 갈피 창을 좁게(너비 약 960px) 쓰면, 작품 페이지의 "8. 등장인물 목록" 머리말에서 제목이 두 줄이 되고 "분류 기준:", "정렬:" 라벨이 글자마다 줄바꿈되며 "새 캐릭터 추가" 버튼 글자도 두 줄이 된다. 전체 화면에서는 깨끗하다.
- **원인**: (1) 캐릭터를 고르지 않아 오른쪽 정보 상자가 비어 있어도 그 자리(340px)가 계속 확보돼서, 960px 창의 본문이 약 550px로 좁아졌다(전체 화면은 약 820px). (2) 머리말이 줄바꿈 허용(`flex-wrap`) 없이 한 줄에 억지로 끼워 넣는 구조라, 모자라면 각 칸 안의 글자가 줄바꿈됐다.
- **해결**: 머리말이 줄 단위로 넘어가게 하고(`flex-wrap: wrap`), 제목, 라벨, 버튼에 `white-space: nowrap`을 줬으며 버튼 묶음은 오른쪽 끝에 붙인다. 너비 1199px 이하에서는 비어 있는 정보 상자 자리를 접는다(`.wikiAside:empty { display: none }`). 960px에서 비어 있으면 본문 920px, 캐릭터를 고르면 정보 상자가 나타나 본문 550px이 되고 머리말은 두 줄로 깔끔하게 나뉜다.
- **재발 방지**: 버튼과 선택 상자가 모인 머리말에는 줄바꿈 허용과 `nowrap`을 같이 쓴다. 테스트는 `WorkDetail.layout.test.js`와 `CharacterGrid.test.jsx`.

## 2026-10-22 작품 페이지의 파란 [[이름]] 링크를 눌러도 반응이 없다

- **증상**: 본문에 `[[리안]]`처럼 쓴 파란 글씨를 눌러도 아무 일도 일어나지 않는다.
- **원인**: 마크다운 렌더러는 링크 클릭 처리 함수(`onNodeClick`)를 받았을 때만 클릭을 처리하는데, 작품 페이지는 이 함수를 넘기지 않았다(편집기 미리보기만 넘김). 이동 로직 `useBacklinkRouter`는 어디서도 쓰이지 않았고, 같은 작품 캐릭터 부분은 "구현 예정" 알림창뿐인 임시 코드였다.
- **해결**: 새 훅 `useWorkBacklink`(`domains/work/`)를 만들어 작품 페이지의 렌더러 4곳과 캐릭터 상세에 연결했다. 같은 작품 캐릭터면 선택 후 카드로 스크롤, 다른 작품이면 이동, 아니면 안내한다. 클릭한 글자는 `innerText` 대신 `textContent`로 읽는다(시험 환경 jsdom이 `innerText`를 지원하지 않음).
- **재발 방지**: 테스트 `WorkDetailPage.backlink.test.jsx`가 연결을, `backlink.test.js`와 `useWorkBacklink.test.jsx`가 동작을 지킨다. 옛 `hooks/useBacklinkRouter.js`는 아직 남아 있으나 쓰이지 않는다.

## 2026-10-22 긴 캐릭터 정보 상자의 수정/삭제 버튼을 누를 수 없다

- **증상**: 작품 페이지에서 속성이 많은 캐릭터를 고르면 오른쪽 정보 상자가 화면보다 길어지고, 맨 아래의 수정/삭제 버튼이 화면 밖에 있어 누를 수 없다. 페이지를 끝까지 내리기 전에는 닿지 않는다.
- **원인**: 정보 상자는 스크롤을 따라다니도록(`position: sticky`) 화면 위쪽에 붙는데, 높이 제한이 없었다. 상자가 화면보다 길면 붙은 위치에서 아래쪽이 잘린 채 그대로 따라다닌다.
- **해결**: 상자에 화면 높이 기준 최대 높이(`max-height: calc(100vh - 150px)`)를 주고 세로 flex 로 바꿨다. 제목·이미지·속성 표·설명은 안쪽 스크롤 영역(`infoboxScroll`)에 넣어 그 안에서만 스크롤하고, 수정/삭제 버튼 줄은 스크롤 영역 밖(상자 맨 아래)에 고정했다.
- **재발 방지**: 화면에 붙어 따라다니는 상자에는 반드시 높이 제한과 안쪽 스크롤을 둔다. 테스트는 `CharacterInfobox.test.jsx`.

## 2026-10-20 장르 테마에서 일부 글자가 배경에 묻힌다

- **증상**: (1) 만화(hero-comic) 테마를 다크 모드로 보면 노란 "편집" 버튼과 제목 없는 헤더의 버튼 글자가 거의 안 보인다. (2) 성황당(joseon-shrine) 테마에서 푸터 버튼에 마우스를 올리면 글자가 어두운 푸터에 묻힌다. (3) 무협 수묵(wuxia-ink)·헌터 홀로그램(hunter-hologram) 다크 모드에서 강조 배경(`gt-macro-accent-bg`) 위 글자가 흐리다.
- **원인**: 글자색이나 배경색 한쪽만 모드에 따라 바뀌는 변수를 썼다. 만화 테마의 글자색(`--cx-ink`)은 다크 모드에서 밝은색으로 바뀌는데 노란 배경(`--cx-yellow`)은 그대로여서 밝은 글자가 노랑 위에 놓였다(대비 1.18). 성황당 호버는 빨강(#a8393a)을 어두운 회색 푸터에 썼고(대비 2.29), 나머지 둘은 다크 모드 강조색이 밝아졌는데 글자가 밝은 색 그대로였다(대비 2.97, 2.88).
- **해결**: 만화는 노란 배경용 글자색 `--cx-on-yellow`(어두운색)를 따로 두고 두 버튼에 썼다. 성황당 호버는 금색(`--js-gold`)으로 바꿨다. 무협 수묵·헌터 홀로그램은 다크 모드에서만 어두운 글자로 덮어썼다(라이트 모드는 그대로).
- **재발 방지**: 배경이 모드와 무관하게 고정인 곳에는 글자색도 고정 변수를 쓴다. 대비 시험은 `themes/themeContrast.test.js`(계산 도구 `themeContrast.js`)에 있고, 새 테마 규칙을 추가할 때 같은 방식으로 대비 4.5 이상을 확인한다.
- **아직 남은 것**: `gt-macro-accent-bg` 가 다른 테마에서 3~4.5 사이, `gt-infobox-desc`·`gt-page-empty` 등이 4.2~4.5인 곳은 이번에 손대지 않았다.

## 2026-10-20 로그탭의 선택된 탭 글자가 안 읽힌다 (어두운 장르 테마)

- **증상**: 작품 페이지에서 `[로그탭:노랑:...]` 같은 로그탭을 쓰면, 선택된 탭 이름(노랑, 사전 등)이 연한 노랑/분홍 배경 위에 거의 같은 밝기의 글자로 보여 읽기 어렵다. 어두운 장르 테마(아포칼립스, 사이버펑크, 호러, 헌터 등)에서만 나타난다.
- **원인**: 선택된 탭에 장르 테마가 글자색을 강제로 덮어쓰는 클래스(`gt-macro-ink`)가 붙어 있었다. 어두운 테마의 이 글자색은 밝은 색인데, 선택된 탭의 배경은 탭마다 정해 둔 연한 파스텔색이라 밝은 글자가 밝은 배경 위에 놓였다.
- **해결**: 선택된 탭에서 `gt-macro-ink` 클래스를 뺐다. 이제 탭마다 정해진 진한 강조색 글자가 그대로 쓰인다(`domains/macro/utils/macroGenerators.js`). 선택되지 않은 탭은 테마 패널색과 짝을 이루는 클래스를 유지한다.
- **재발 방지**: 고정된 연한 배경 위에는 테마가 글자색을 덮어쓰는 `gt-macro-ink` 계열 클래스를 붙이지 않는다. 테스트는 `macroGenerators.test.js`.

## 2026-10-15 메모장에서 새 폴더가 만들어지지 않는다 (exe)

- **증상**: 갈피 exe의 메모장에서 폴더 추가 버튼(최상위/하위)과 폴더 이름 변경을 눌러도 아무 창도 뜨지 않고 폴더가 만들어지지 않는다. 새 메모 만들기는 정상이다.
- **원인**: 폴더 이름을 `window.prompt()`로 물었는데, Electron(exe의 화면 엔진)은 `prompt()`를 지원하지 않아 호출해도 입력 창이 뜨지 않는다. 브라우저(`npm run dev`)에서는 되기 때문에 개발 중에는 드러나지 않았다.
- **해결**: 앱 안의 입력 모달(`components/common/TextPromptModal.jsx`)과 호출 함수 `askText`(`utils/askText.js`)를 만들어 폴더 추가와 이름 변경이 그것으로 묻게 했다. 작품 영구 삭제 확인 때 쓴 방식과 같은 접근이다.
- **같은 원인이 있던 다른 곳**: 책갈피 이름(Ctrl+K), 상용구 폴더 추가/이름 변경, 일괄 편집의 속성 추가/순서 이동도 같은 증상이었고 2026-10-15에 모두 `askText`로 바꿨다. 코드에 남은 `prompt()` 호출은 `askText`의 대체 경로(입력 모달이 없는 환경용) 한 곳뿐이다.
- **재발 방지**: 새 입력 UI에는 `prompt`/`confirm` 대신 `askText`를 쓴다. 테스트는 `window.prompt`가 에러를 던지는 환경(Electron과 같은 조건)으로 시험한다.
